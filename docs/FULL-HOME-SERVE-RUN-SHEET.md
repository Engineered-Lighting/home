# Full Home and Den rollout

Use the integrated `codex/full-home-serve` checkout. The Home candidates are `858e8dd9` and `1d73bb1a`. The Den labels and Qwen producer is based on `b3002536`, the live coordinator on `3774803b`, its policy on `11f694de`, and the offline C12 FC13 byte layout on firmware `cf1c325`. Record the exact built revision and release digest for the gateway, Den producer, BFF and lighting service.

## Local gate

Use Node 24.14.1. Run `npm ci --no-audit --no-fund`, `node node_modules/playwright/cli.js install chromium`, and `node tools/build-app-jsx.mjs`. Run `node --test tools/test-den-live-serve-browser.mjs` and `node tools/run-web-gateway-look-only-tests.mjs`. The browser harness uses the repository test TLS certificate, fake upstreams and disposable profiles. The default Windows sandbox can reject loopback connections before Chromium launches. Run these synthetic tests with loopback access and use the recorded child output to distinguish that error from a failed build or process bind.

Run the coordinator, room labels, body and computed C12 Python suites under `tools/den-live`, the BFF lighting client tests, and the Core lighting API and service tests. Keep the private TLS and edge services on synthetic fixtures for local validation.

## Owner preflight and rollout

1. Record the current Home deploy, the active Den scan and equipment registration, the existing private lighting release, the Serve mapping and the Funnel status. Check the effective tailnet grants and device shares for the normal Home port before granting it write access. Confirm the dedicated gateway port is bound to loopback and used exclusively by Serve with its PROXY prefix. Keep the ordinary gateway listener and its existing authentication.
2. Deploy the private lighting service and BFF with their existing TLS configuration and per-home signing credentials. Provision two independent 64-hex service credentials. The gateway relay file is set by `HOME_WEB_SERVE_LIGHTING_RELAY_CREDENTIAL_FILE`; the matching BFF file is selected by the compose setting `HOME_AGENT_SERVE_LIGHTING_BFF_RELAY_FILE`. Select the second credential in the BFF with `HOME_AGENT_SERVE_LIGHTING_BFF_CORE_FILE` and in Core with `HOME_AGENT_SERVE_LIGHTING_CORE_FILE`. The compose values are mounted container file paths. Verify signed inventory from both homes using their existing light-only services before enabling the card. Record the current private service image and configuration for rollback. Keep all secret values in the private mounts.
3. Land the pinned integrated Den producer in the existing reviewed `claude/den-live` installer lane, then install that clean, committed release through the existing workflow. Enable `body_v2` in the producer config. Configure `coordinator.mode` as `virtual`, its `lights` list with the existing Den HA light IDs for shadow readout, its `virtual-fixtures.json` service credential with the overlay’s exact fixture IDs (including socket-generated IDs), `real: false`, renderer optical origins and horizontal forward axes, and `virtual_binding` with the installed equipment document's `binding`, `equipment_revision` and `equipment_digest`. Stage the root-only JSON and add `LoadCredential=virtual-fixtures.json:/etc/den-live/private/virtual-fixtures.json` in an owner-managed service drop-in. Verify that producer `/body-v2` emits only `den-live-body-2` and that `/coordinator/virtual` reports the control revision and producer clock. The legacy HA switch is independent of this state. Keep the existing Hue controller running. The v2 figure uses generated torso and limb geometry only and needs a supported pose.
4. Configure `HOME_WEB_SERVE_PORT` and `HOME_WEB_SERVE_ORIGIN` for the existing normal Home HTTPS address. Set `HOME_WEB_DEN_LIVE=1`, `HOME_WEB_DEN_BODY_V2=1` and `HOME_WEB_DEN_VIRTUAL=1` after verifying the matching upstream contracts. Use `tailscale serve --bg --tls-terminated-tcp=443 --proxy-protocol=1 127.0.0.1:5182` for the documented port, or use the verified dedicated port. Leave optional legacy proxies at their current settings. Remove the old look-only option after verifying the replacement. Check Serve and Funnel status again.
5. On fresh desktop and phone browser profiles, open normal Home and the Den without entering a credential. Verify a rendered figure in day and night conditions, save and restore a room label, and test On, Off, Stop and Resume. As a separate check, change and restore one approved ordinary light at each home using the cross-home card. Disconnect Tailscale on cellular and verify a fresh visit is unreachable and a warm tab loses live data and control.
6. In room light at the real sofa, check that the rendered beam reaches the page, follows a shift, and darkens when reading stops. Match the displayed fixture trace ID to the local `coordinator-c12-computed.jsonl` entry and check `byte_checked: true` and `sent: false`. Record the pinned scan and equipment revisions and the actual page-to-beam check. Keep the incumbent Hue controller in charge. Desk transport is a separate approved stage and this gate has no soak.

## Rollback

Disable the affected Den route flags or the new lighting action before downgrading a producer or service. Preserve the lighting journal and outcome lookup for submitted operations. Restore the recorded gateway configuration and Serve mapping, then confirm the prior normal or look-only route and ordinary ingress behave as before. Keep private receipts and real frames on the owner's systems.
