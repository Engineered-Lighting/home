title: Ladder levels 1 and 2 runner for the lighting belief questions
target: backend
type: added
---

Adds `tools/public_story_eval.py`, the offline runner that sends public-dataset rows through the five lighting belief questions behind the egress gate (dry run by default, `--execute` with a hard call cap, cached answers and receipts confined to the private experiments directory, packet cameras named after each question's room, recall at the a-priori threshold as the level-1 metric with a per-scene breakdown), and `EGRESS-RECORD.md`, the schema, scopes, file mode, toggle mirror and env switch of the egress record.

`--level 2` adds the bounded visual level: each row names the rich observation the observer's batch runner wrote for that window, and the packet is built from that typed observation the way the belief publisher will build it (dimension descriptions become the camera's claims, posture and activities become its account, the dataset's caption, class names and targets are never read into it). Because the leak guard knows household vocabulary and not dataset vocabulary, an explicit check refuses any row whose packet carries a class id, a class name or a target word, and reports it per row; so is a missing or empty rich observation, which never aborts the run. Scoring keeps level 1's probability-only reduction, three-way targets and sensitivity table, chooses recall or precision-and-recall per question from the labels actually present, and adds the two consequence flags the plan names (`disruptive_brightening`, `darkness`) and calibration bins with n. The answer cache key includes the level and the rich-observation digest, so the levels never share an entry.

Level 2 now reads the observer batch's own output. A row names its rich observation as a path relative to the cache root given by `--observations` (the form the batch writes, alongside the window's selection fields and `observation_model`); an inline observation still works and an absolute path is taken as given only when no cache root is supplied, for debugging a single file; whenever `--observations` is given, containment applies to every reference, relative or absolute, and one that resolves outside the root is refused. An observation whose own id, window digest or model does not match the row that named it is refused and counted (`counts.observations_mismatched`), so a mispaired batch is loud rather than quietly scored. and a row that names no observation at all is one refused row (`counts.observations_missing`, `counts.observations_unnamed`) rather than a refused file, because the batch writes a line per selected window whether or not it observed that window.

Two guards were measured against the real selection and tightened. The taxonomy exemption is now per packet field instead of per run: the manifests name many classes after the observer's own posture and activity words, so dropping those terms globally stood the class-name check down completely on the whole of the strata the acceptance thresholds name; the exemption now applies only to `$.cameras.*.account`, the one field this runner fills from that closed vocabulary, while the claims (the model's free text) keep the full check, and `counts.vocabulary_exempt_rows` plus `level2.vocabulary_exempt_terms` record how much stood down. And because every refusal shrinks the denominator the acceptance ratios are computed over, `run.json` and `scores.md` now carry, per question, the rows selected for it, the rows actually scored and the coverage between them, and `--min-coverage F` fails the run (status `coverage_below_minimum`, exit 3, receipts still written) when a question falls below `F`; a dry run scores nothing by construction and records the floor as unchecked.
