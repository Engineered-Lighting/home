# app/ — the Home desktop client

A [Tauri 2](https://tauri.app) app. Rust shell + a small React frontend
served from disk. No bundler — JSX is compiled in-browser via Babel
Standalone.

## Build prerequisites

- Rust ≥ 1.75 (via [rustup.rs](https://rustup.rs))
- MSVC Build Tools 2022 with "Desktop development with C++" workload
  (on Windows) or Xcode CLT (on macOS)
- Tauri CLI: `cargo install tauri-cli --version "^2.0" --locked`
- WebView2 runtime (preinstalled on Windows 11)

## Layout

```
app/
├── src/                    # frontend served by the Tauri webview
│   ├── index.html
│   ├── home-tokens.css     # design tokens (Geist Sans+Mono, dark+light)
│   ├── home-tauri.jsx      # Tauri 2 wrappers + localStorage helpers
│   ├── home-ha.jsx         # HA WebSocket client + pipeline mapping
│   ├── home-icons.jsx      # IconMic / IconSend / IconSun / etc.
│   ├── home-events.jsx     # turn-block + event renderers
│   ├── home-script.jsx     # SCRIPT (scripted /demo conversation)
│   ├── home-app.jsx        # HomeApp main component
│   └── home-mount.jsx      # standalone ReactDOM.createRoot mount
└── src-tauri/              # Rust shell
    ├── tauri.conf.json     # window: 420×720, frameless, resizable
    ├── Cargo.toml
    ├── build.rs
    ├── capabilities/default.json   # window + http plugin perms
    ├── icons/              # generated by `cargo tauri icon`
    └── src/main.rs         # tauri::Builder + plugin registration
```

## Develop

```bash
cd app/src-tauri
cargo tauri dev          # opens the borderless 420×720 window with hot reload
```

The webview loads from `app/src/` directly — edit a `.jsx` file and
the change appears on next Babel transform (refresh the window).

## Build a release

```bash
cd app/src-tauri
cargo tauri build        # produces target/release/bundle/msi/Home_x.y.z_x64_en-US.msi
```

`cargo tauri build` triggers WiX to bundle the `.msi`. First run
downloads ~30 MB of WiX binaries. Subsequent builds reuse them.

## Release workflow

Desktop releases are prepared through GitHub Actions:

1. Run **prepare desktop release** with a SemVer version such as `0.1.1`.
2. Review and merge the generated release PR.
3. Run **tag desktop release** for the same version from `main`.
4. The tag push triggers the Tauri installer build and creates a draft GitHub
   Release with notes from `CHANGELOG.md`.

Every user-facing or deploy-relevant change should include a
`changes/unreleased/*.md` fragment. Release preparation compiles those fragments
into `CHANGELOG.md` and archives them.

### Apartment 3D assets

The desktop installer does not bundle `app/data/apartment` in v1. Those files
are local runtime data, not release artifacts. Apartment cloud/scan/mesh views
need the relevant `points.ply`, `apartment.ply` or `apartment.spz`, `mesh.glb`
or `collision.glb`, and metadata files provisioned on the machine running the
desktop app.

## Regenerate icons

```bash
python tools/make-icon.py
cargo tauri icon app/src-tauri/icons/source.png
```
This regenerates `icon.ico`, `icon.icns`, and the `Square*Logo.png`
sizes Tauri's bundler expects.

## Notes for editors

- The frontend has no bundler. Every `<script type="text/babel">`
  block in `index.html` is independent and shares globals via
  `window.X`. New modules need an `Object.assign(window, {...})` at
  the bottom.
- `tauri.conf.json` `"decorations": false` is what makes the window
  frameless. Drag region is wired via `data-tauri-drag-region` on
  `HomeHeader`.
- The HA WebSocket client (`home-ha.jsx`) is the only place that
  knows about HA's pipeline event shapes. Add new events in
  `extractIntentEnd` / `extractIntentProgress`.
- Persistence is plain `localStorage` (see `home-tauri.jsx`). Cap is
  ~200 events for the conversation log.
