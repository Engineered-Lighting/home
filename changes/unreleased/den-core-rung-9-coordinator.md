Adds rung 9's coordinator to `tools/den-core`, offline and sending nothing: both arms through one light-model adapter, Decisions with requested and applied scenes and recipients, the seed Look's glare limit on free bulbs with conflicts logged, and `actuation = shadow` in the runner. A model file goes through den-light's own `predict.py`, loaded by file path and pinned by hash in the log, so `check.py` refuses when it changes; a model marked `fake: true`, or a checkout with no `tools/den-light`, goes through a fake built from rung 8's plan and is labelled so. `score.py` reports the anticipation and stability surrogates and predicted service at the owner's marks, and refuses a scored run while any slot in `rung9-gate-v0.json` is open or the model or its backend is fake, naming why. Which blocks form each surface is one of those slots, so nobody is scored at the whole view's mean by default. When the coordinator ran, `run.py` also writes `decisions.jsonl` and `surfaces.json` beside the log, for rung 10. A Decision says each bulb's `level` and `cct_k` in canon names beside the Hue keys, null and never 0 when a level is unknown, and `run.py --light-states` lets it name the newest LightState at or before it, as a reference that changes nothing else it says. A hold's footprint and bound work per block, and a Decision fits its log line whatever the map or the number of tracks seen, listing the whole map while it fits, counting what it left off, and keeping a track over the glare limit to the last. The grid does have a limit: under P1 to P3 each held bulb's footprint costs one hex digit per 4 blocks, so with every bulb held `block_px` 8 or coarser fits, the proposed 20 included, and `block_px` 5 or finer stops the run with `decision line over 16384 bytes` and no log. Hold fixtures V6-V8 and V62-V64 run under every compensation option and stay not admitted until the owner decides. The four synthetic evenings stay byte-identical. Every file `run.py`, `score.py`, `check.py` and `validate.py` read is refused with one sentence and exit 2 when it is UTF-16 (what PowerShell 5.1's `>` writes), missing, malformed or the wrong shape, down to what is inside a light model, a mark, `--truth`, or a log's header, logged config and any input line no replay can run; a missing or wrong-shaped `--truth` used to read n/a. A log of the right shape whose replay comes out different, because a line was changed or is wrong inside, fails with exit 1 instead, and `validate.py` says so check by check, unless `score.py`'s own report can't read the value, which is one sentence and exit 2. The replay doesn't see an edit to a field it doesn't use, such as a facts line's `latency_s` or the header's `sources`: such a log still reads `OK`. `--journal`, `--status`, `--corrections`, `--live-commands` and `--lights` used to read UTF-16 and now refuse it too, a UTF-8 byte-order mark is read everywhere, `run.py` and `score.py` no longer exit 1 on what they refuse, and a time no run could reach is refused where it used to loop until memory ran out.

For the den simulation the coordinator also has a spot mode. With `config["channels"]` and `actuator_domain` `virtual-den-4` it writes canon Decisions for one spot per channel: every spot off unless someone is reading at a spot, each fixture asked through the lighting brain's own `aim.py` with each refusal named in `skipped`, one beam per reader at the gate's 300 as a declared target in the model's unit, the aim and its `target_m` on the record only, a dark move then a fade in, and `aim_status` never `settled`. Its rule and the brain's thresholds are pinned only in that mode, so every Hue Decision stays byte-identical. It is synthetic plumbing on a fake model, `score.py` refuses it, and nothing is sent.
