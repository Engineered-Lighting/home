---
title: Recorded stage graph, replay timeline and compact replay reads for the Perception Lab
target: backend
type: added
---

The Lab controller adds three read-only, bounded endpoints for the new graph UI, routed through the web gateway, the browser transport and new typed native operations: `sessions/{sid}/graph` shows what was recorded at a live or replay cursor for each source (distinct implemented, provisioned, producing, freshness and per-request consumption flags, versions, failures and a redacted snippet of at most 2 KiB), and for each arm the chain from specialist output through saved prepared evidence and the exact admitted JEV request to its result, with later decision and action stages shown inactive. Each arm's setup and per-source declarations come from the experiment activation recorded by the cursor; values only today's catalog knows are labelled as such for a live cursor and left empty for a replay cursor, and a request older than the scan bound is reported as unknown rather than absent. `sessions/{sid}/timeline` returns deterministic, downsampled per-arm perception and JEV tracks that keep the latest item per time bucket across the whole range, with delivery gaps, failure reasons, transitions, worker and recording events, labels, bookmarks, context receipts and clock-mapping status (each track says when its row bound was reached, so totals are never overstated as complete), and `sessions/{sid}/replay` returns only the causal outputs and room context a replay seek needs. Reads never run inference or write, only show evidence available by the cursor, mark the design's proposed sources as proposed without values, and stay within 1 MiB; see docs/PERCEPTION-LAB-GRAPH-CONTRACT.md.
